# Plan — Cuotas del período (M2)

Deriva de la spec aprobada `02-DOCS/wiki/sdd/specs/cuotas-m2.md` y respeta la
constitución v1.0.0. A diferencia de M1, este módulo **introduce una migración
de esquema** (tabla `periodo_cuota`), por lo que es tier 2 y va por ASDD
completo.

## 0. Global constraints

- Montos enteros en CLP (constitución 3).
- Período `AAAA-MM`, único (spec §What it must respect).
- Deuda derivada: socio `activo=1` sin `pago_mes` para ese período (constitución
  15; spec AC4–AC7).
- Monto por tipo sale de `nivel_cuota`, no se duplica (spec, suposición).
- Sesión obligatoria en rutas de cuotas → 401 (constitución 7).
- Migración: generar → leer SQL → aplicar; nunca `drizzle-kit push`
  (constitución 5).
- `typecheck` y `build` en cero para merge; `npm test` verde.

## 1. Context & constraints

- Spec `§Acceptance criteria` AC1–AC7; `§What it must respect` (período único,
  deuda derivada, monto por nivel).
- Constitución 3, 5, 7, 15.
- Esquema existente: `socio` (estado, activo), `nivel_cuota` (monto por tipo),
  `pago`/`pago_mes` (cobertura de períodos). `periodo_cuota` es la pieza nueva.

## 2. Architecture

```
web (React)                     api (Hono)
┌────────────────────┐  /api    ┌────────────────────────────┐
│ Shell (nav)        │ ───────► │ app.ts → cuotas/routes.ts   │
│  └ CuotasPage      │  fetch   │   ├ requireSession (401)    │
│     └ lib/api.ts   │          │   └ cuotas/repo.ts          │
└────────────────────┘          │        ├ periodo_cuota      │
      TanStack Query            │        ├ nivel_cuota        │
                                │        └ deuda (JOIN socio  │
                                │          LEFT JOIN pago_mes)│
                                └──────────── drizzle ──► MariaDB
```

- **Nueva entidad `periodo_cuota`**: registra el mes y el vencimiento. La deuda
  NO es una tabla: es una consulta derivada.
- **Cálculo de deuda**: socios activos (`activo=1`) que no tienen `pago_mes`
  para el período, con su monto desde `nivel_cuota` por `socio.estado`.

La decisión central (ya elegida por el usuario): **período persistente + deuda
derivada**, no generación masiva. Se defiende contra la spec: evita miles de
filas al año y la sincronización con altas/bajas; el estado de cuenta se deriva
del padrón vivo.

## 3. Interfaces & contracts

- `GET /api/cuotas/periodos` → lista de períodos con `{ id, periodo, diaVencimiento, totalDeudores }`.
- `POST /api/cuotas/periodos` → 201 con el período; 409 si el mes existe; 400 si mal formado.
- `GET /api/cuotas/periodos/:id/deuda` → `{ periodo, total, filas: [{ socioId, rut, nombre, tipo, montoClp }] }`.
- Todas exigen sesión (401 sin cookie).

## 4. Data model & flow

- Tabla `periodo_cuota`: `id`, `periodo` (AAAA-MM, único), `dia_vencimiento`
  (1–31), `created_at`.
- Deuda (consulta derivada): `socio` con `activo=1`, LEFT JOIN `pago_mes` sobre
  `socio.id = pago_mes.socio_id AND pago_mes.periodo = :periodo`, filtrando
  `pago_mes.id IS NULL`; monto desde `nivel_cuota` por `socio.estado`.

| Criterio | Nivel | Qué afirma | Qué finge |
|---|---|---|---|
| AC1 (sin sesión → 401) | integración (vitest) | ruta corta sin cookie | — |
| AC2 (crear período) | integración | inserta y lista | base de prueba |
| AC3 (duplicado → 409) | integración | unicidad | base de prueba |
| AC4 (deuda = activos sin pago) | integración | JOIN correcto | base de prueba con datos |
| AC5 (inactivo excluido) | integración | filtro activo=1 | base de prueba |
| AC6 (mes inválido → 400) | unidad (validador) | regex período | — |

Suite Vitest para validadores (puro) y rutas (contra base de prueba), más un
script re-ejecutable `verify-cuotas.mjs`.

## 6. Sequencing & dependencies

1. `shared`: validadores (`periodoCuotaSchema`, `crearPeriodoCuotaSchema`).
2. `shared`: schema `periodo_cuota` + generar migración + leer + aplicar.
3. `api`: repo (periodo + deuda derivada) → rutas → montaje.
4. `web`: cliente + página Cuotas.
5. Tests Vitest + verificación re-ejecutable.
6. Revisión adversarial tier 2 + cierre.

## 7. Risks & open decisions

| Riesgo | Disparador | Impacto | Mitigación |
|---|---|---|---|
| Migración de esquema (tier 2) | nueva tabla `periodo_cuota` | bloquea push | ASDD + revisión + aprobación humana |
| Deuda derivada mal calculada | JOIN pago_mes incorrecto | cobro equivocado | tests de integración con datos (AC4/AC7) |
| Monto por tipo sin datos | `nivel_cuota` vacío | deuda sin monto | montos de prueba en M2; reales en M5 |
| `socio.estado` vs `nivel_cuota.tipo` desalineados | estado libre | tipo sin nivel | validar mapeo; documentar en M5 |
